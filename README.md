# 3x-ui Subscription Aggregator

Мультипользовательский агрегатор подписок поверх [3x-ui](https://github.com/MHSanaei/3x-ui). Пользователь подключает свои панели по нативному API-токену и получает единую ссылку подписки для VPN-клиентов (v2rayTun, v2rayNG, Hiddify и др.).

Поддерживается 3x-ui начиная с `3.4.2`, только совместимые релизы major-ветки `3`. Более старые версии и будущие major-версии отклоняются при проверке подключения.

## Что есть

- **Админ-панель приложения** — bootstrap-админ из конфига выдаёт одноразовые приглашения и управляет пользователями.
- **Кабинет пользователя** — отдельные разделы для серверов, inbound'ов, подписок и локальных групп.
- **Безопасное массовое подключение** — из inbound, сервера, подписки или группы открывается общий сценарий «кого → куда → проверка → подключить». Исходные подключения сохраняются.
- **Нативный API 3x-ui** — только Bearer-токены; вход в панель по логину/паролю и cookie fallback отсутствуют.
- **Мультипротокольные подписки** — сервис получает готовые subscription links нативным API панели и объединяет их в base64-ответ.
- **Persistent SQLite** — пользователи, панели, сессии, приглашения и зашифрованные API-токены хранятся локально.

## Эндпоинты приложения

|------|----------|

| `GET /dashboard/groups` | Сохранённые локальные аудитории подписок |
| `GET/POST /dashboard/connections/*` | Выбор аудитории, preview и массовое подключение к inbound |
| `GET/POST /dashboard/servers/new` | Добавить панель |
| `GET/POST /dashboard/servers/{id}` | Редактировать панель |

## Быстрый старт

### 1. Конфиг и секреты

```bash
cp config.example.yaml config.yaml
cp Caddyfile.example Caddyfile
read -rsp 'Admin password: ' ADMIN_PASSWORD && export ADMIN_PASSWORD
echo
read -rsp 'Master key: ' XUISUBAGG_MASTER_KEY && export XUISUBAGG_MASTER_KEY
echo
```

`config.example.yaml` ссылается на эти переменные:

```yaml
admin:
  login: "admin"
  password: "${ADMIN_PASSWORD}"
master_key: "${XUISUBAGG_MASTER_KEY}"
```

До запуска замените `sub.example.com` в первой строке `Caddyfile` на свой публичный домен. В `config.yaml` задайте тот же внешний HTTPS URL без завершающего `/`, например:

```yaml
public_url: "https://sub.example.com"
```

Домен в `Caddyfile`, значение `public_url` и адрес, который вы откроете в браузере, должны совпадать. DNS-записи домена должны указывать на хост с Caddy.

`master_key` обязателен для сохранения и замены API-токенов: токены шифруются AES-256-GCM перед записью в SQLite. Сделайте защищённую резервную копию `XUISUBAGG_MASTER_KEY` отдельно от базы. При утрате ключа сохранённые токены не расшифруются и их придётся заменить. Без ключа приложение запускается и показывает панели, но не сохраняет токены.

Bootstrap-админ создаётся только при первом запуске. Его пароль относится к этому приложению, а не к 3x-ui.

### 2. API-токен 3x-ui

Для каждой панели:

1. Обновите 3x-ui как минимум до `3.4.2` в major-ветке `3`.
2. В настройках панели создайте отдельный именованный API-токен для агрегатора, чтобы его назначение было видно при аудите и отзыве.
3. Панель показывает plaintext токена один раз. Сразу скопируйте его, вставьте в форму сервера агрегатора и сохраните безопасно до успешной проверки.
4. Используйте HTTPS URL панели и оставьте проверку TLS включённой.

После обновления агрегатора старые строки серверов остаются в базе и видны как «требуется токен», пока вы не настроите API-токен. Существующие значения логина и пароля панели runtime не читает и не изменяет; для новых строк в физических legacy-колонках записываются пустые значения. Fallback на старые credentials отсутствует.

### 3. Запуск

Docker Compose:

```bash
docker compose up -d
```

Compose передаёт `ADMIN_PASSWORD` и `XUISUBAGG_MASTER_KEY` из окружения хоста. SQLite хранится в `./data`, Caddy получает TLS-сертификат.

Локально:

```bash
go run ./cmd/aggregator -config config.yaml
```

После запуска откройте `/login` на URL из `public_url` — для примера выше это `https://sub.example.com/login`. Создайте приглашения и добавьте панель с API-токеном. После проверки подключения мастер предложит скопировать VLESS inbound и перейти в общий сценарий подключения подписок.

Группа — это сохранённый локальный набор `subId`, а не сущность 3x-ui. Её можно открыть в разделе «Группы» и явно подключить к любому доступному VLESS inbound. Изменение состава группы само по себе не меняет серверы. Перед массовой операцией показывается preview: сколько подписок будет добавлено, сколько уже подключено и сколько сейчас недоступно. Повторный запуск не создаёт дубликаты, исходные подключения сохраняются.

## Как работают подписки и stale fallback

URL имеет вид `https://sub.example.com/sub/{user_prefix}/{sub_id}`. `user_prefix` — случайный 24-символьный hex пользователя. Без знания prefix нельзя перебрать чужие subscription id.

Сервис получает от каждой панели нативные multi-protocol subscription links, объединяет, сортирует и кодирует их в base64. Если панель временно недоступна, последний успешный snapshot и ссылки могут обслуживаться из памяти как stale fallback, чтобы избежать flapping. Этот fallback не записывается в SQLite и полностью теряется при перезапуске процесса; после старта данные появятся только после успешного опроса панели.

Операции создания и копирования inbound ограничены VLESS. Сами subscription links возвращаются в тех протоколах, которые выдаёт нативный API 3x-ui.

## Безопасность

- Пользовательские пароли приложения хешируются bcrypt. Session cookie имеет `HttpOnly`, `SameSite=Lax` и `Secure` при `cookies_secure: true`.
- API-токены 3x-ui зашифрованы в SQLite; храните резервные копии `master_key` и базы раздельно.
- Токен 3x-ui имеет полномочия администратора панели. Его утечка даёт большой blast radius: доступ ко всем клиентам и inbound-ам этой панели. Выдавайте отдельный токен агрегатору, ограничивайте сетевой доступ и быстро отзывайте скомпрометированные токены.
- Используйте HTTPS с валидным сертификатом. `insecure_skip_verify` отключает проверку сертификата и позволяет MITM перехватить Bearer-токен; включайте только временно в изолированной доверенной сети.
- Не используйте HTTP через недоверенную сеть: Bearer-токен передаётся в каждом запросе и при перехвате сразу пригоден для доступа к панели.
- `/sub/{prefix}/{sub_id}` публичен по дизайну для VPN-клиентов. Считайте URL секретом.

### Ротация и отзыв токена

1. Создайте новый именованный токен в 3x-ui.
2. Откройте сервер в агрегаторе, вставьте новый токен, выполните проверку и сохраните.
3. Убедитесь, что синхронизация и подписка работают.
4. Отзовите старый токен в 3x-ui.

Если токен сначала отозван или скомпрометирован, немедленно отзовите его в панели, затем создайте новый и обязательно обновите сохранённый токен в агрегаторе. Старый сохранённый токен сам не обновится.

## База и резервное копирование

Миграции SQLite выполняются при старте. Физические legacy-колонки `servers.username` и `servers.password` сохраняются для совместимости схемы: существующие значения runtime не читает и не изменяет, а при создании новых строк записывает в эти колонки пустые placeholders. Для полного восстановления нужны `data.db` и правильный `master_key`.

## Проверка реальной панели после обновления

Автотесты используют локальный fake нативного API. Для ручного smoke с 3x-ui `3.4.2+` major `3`:

1. Создайте тестовый именованный токен и добавьте HTTPS-панель в агрегатор.
2. Нажмите проверку подключения и дождитесь успешной синхронизации.
3. Откройте subscription URL и декодируйте base64, убедившись, что ссылки принадлежат панели.
4. Выполните attach и detach группы, затем безопасное редактирование тестового inbound.
5. Проверьте access log панели: запросы должны идти только под `/panel/api/...`; запросов к panel login и legacy embedded-client endpoint быть не должно.
6. Выполните ротацию токена по инструкции выше.
